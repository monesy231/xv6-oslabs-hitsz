# 页表实现过程

> 原始实验记录。文中的测试数据和补丁校验值对应当时的环境与交付件。当前归档的运行步骤与补丁见本目录的 [README](../README.md)。

**实验思路：**先弄清「谁拥有页表页、CPU 当前用哪张表、映射何时更新」，再落地打印、私有内核页表与共享用户映射。本说明记录从需求核对到实现、调试、补丁验证的过程，供复现和验收复习。

## 一、确认要求与基线

按新版《操作系统实验指导书—2026 秋》Lab4 章节整理验收项：回答任务零四问，补齐 `vmprint()`，建立进程私有内核页表，并接入框架提供的 `copyin_new()`／`copyinstr_new()`。

保持同一仓库及原有实验分支安排，仅在本地提交，交付 `commit.patch`、实验报告和本说明；不改动框架 `kernel/vmcopyin.c`。未提供 Lab4 专用报告模板，报告据指导书组织。

基线检查显示缺少 `vmprint`、独立内核页表以及新拷贝函数调用路径。此前基线运行出现三项测试失败；这些历史临时日志已清理，因此它们仅作为过程背景，本轮最终验收以重新执行的结果为准。

## 二、设计与落地

实现围绕三个问题展开：**谁拥有页表页、CPU 当前使用哪张表、映射何时更新**。

首先，以递归遍历补齐页表打印，通过 V 和 R/W/X 区分目录与叶子，并累积索引形成虚拟地址。只在初始进程 `exec` 后打印，便于观察。

其次，在进程结构中保存私有内核页表和永久栈物理地址。创建时复制必要内核映射并补内核栈；调度时切换 SATP、刷新 TLB，返回调度器后恢复全局表。已有陷入路径保存当前 SATP，无需额外修改 `trap.c`。分配失败和进程退出都回收私有页表结构，避免释放共享内核物理页或按槽位分配的栈。

最后，选择指导书推荐的末级页表共享方案：把用户区对应的 **96 个 L1 项**同步进私有表。这样既能让硬件直接翻译用户地址，又保留用户叶子的权限标志。同步分别接入首次进程创建、子进程复制、程序替换、内存伸缩；释放前先清除共享引用，确保用户页表只释放一次。用户上界固定在 PLIC 之前，防止地址重叠。

实际修改限定于 `defs.h`、`exec.c`、`proc.c`、`proc.h`、`riscv.h` 和 `vm.c` 六个内核文件。

## 三、验证中暴露的问题及处理

此前第一版实现和补丁还原运行都曾得到官方 **100/100**，并出现 ALL TESTS PASSED。由于旧临时日志不再保留，而且随后有权限修复，这些结果不能替代当前版本的最终验证。

额外边界检查复现了一个官方测试未拦住的问题：栈保护页的 PTE 有效、U=0，但它仍在内核页表中；直接启用 SUM 后读取该地址，并不会自动按用户身份检查权限。以该页作为 `write()` 源地址时曾返回 1，说明读保护被绕过。

修复放在 `vm.c` 包装层：逐页检查 V/U/R，再调用框架新函数。固定长度要求完整范围通过；字符串仅允许读取连续可读前缀，让有效页面里的 NUL 能正常终止，不因后续保护页而提前拒绝合法字符串。拷贝临界区暂时开启 SUM，并恢复进入前状态。实际复制仍通过 `_new` 和硬件地址翻译完成，但权限核验保留逐页 `walk()`，不把这一实现描述成彻底没有软件遍历。

框架固定长度函数拒绝恰好到达 <code>p->sz</code> 的范围，这一原有条件保持不动。新增检查和测试结论应与这一限制区分。

2026 年 10 月 16 日，权限修正后的原工程完整评分为 **100/100**，出现 ALL TESTS PASSED。五组附加测试全部通过，覆盖跨页字符串、保护页前 NUL、PLIC 与 INT\_MIN 限制、跨 2 MiB 增缩容、fork 数据隔离与 32 次槽位复用、保护页读取拒绝。

六个内核文件已保存为本地提交 `f67c335`，未上传。生成的 `commit.patch` 为 11484 字节；在本地临时克隆中检出干净 `pgtbl-26-fall`（`6e312f7`），执行 `git apply --check`、实际应用及完整 `make grade`，再次得到 **100/100** 和 ALL TESTS PASSED。还原树的差异与最终补丁逐字节相同。两次实际测试均从干净构建开始，未修改框架拷贝实现、测试程序或评分器。

## 四、复现与交付检查

在仓库 `pgtbl` 分支执行 `make clean`、`make grade`。使用 `make qemu` 启动后，运行 `kvmtest`、`stats stats`、`usertests`，分别核对私有页表、生效的新拷贝路径及系统回归。观察页表打印时重点看索引、层级、虚拟地址和权限，物理地址可能随运行变化。

补丁复现应使用另一份干净 `pgtbl-26-fall` 初始代码，执行：

```bash
git apply --check /实际路径/commit.patch
git apply /实际路径/commit.patch
make clean
make grade
```

先检查后应用，并在应用后的副本重新测试，才能证明补丁独立可还原。上述路径需替换为实际交付位置，不应直接对已经包含改动的工作树重复应用。
