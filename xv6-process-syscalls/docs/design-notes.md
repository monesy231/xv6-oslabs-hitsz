# 系统调用实现笔记

> 原始设计笔记。编译与运行命令见本目录的 [README](../README.md)。

**实验思路：**先弄清调用链，再处理状态与并发。本实验围绕三个问题展开：进程退出时如何观察父子关系，父进程如何选择阻塞或非阻塞等待，以及用户程序如何主动让出 CPU。实现时先理解现有机制，再在原有流程中增加必要功能，重点检查状态、锁、参数和返回值是否相互一致。

## 一、准备与阅读顺序

先确认处于 Lab2 的 syscall 分支，以 `syscall-26-fall-v2` 作为补丁基准，保存其他实验的改动。

阅读顺序：

1. 阅读 `proc.h` 了解进程控制块
2. 阅读 `proc.c` 了解 `exit`、`wait`、`yield`、`scheduler`
3. 阅读 `syscall.c` 和 `sysproc.c`，把系统调用号、参数提取和内核函数连起来
4. 对照用户测试，明确每项要求的输出和返回行为

## 二、系统调用是怎样到达内核的

用户函数并不直接调用内核 C 函数。调用链如下：

1. `usys.pl` 生成的入口把系统调用号放入 `a7`，执行 `ecall`，陷入内核
2. `usertrap()` 随后调用 `syscall()`
3. `syscall()` 根据 <code>trapframe->a7</code> 查找 `syscalls[]`
4. 参数来自 `a0`～`a5`，处理结果写回 <code>trapframe->a0</code>

理解这条链后，才能判断一个新接口是缺少用户入口、调用号、分发表，还是处理函数。

## 三、exit：关键是输出时机与父子关系

- 父进程信息应在确认父指针后读取
- 子进程信息应在托管给 init 之前读取，否则观察到的关系已经改变
- 实现中按**父锁到子锁**的顺序加锁；发现等待期间父指针变化则重试
- 在 `reparent()` 中输出孩子后才改其 `parent`
- 状态名称按课程规定映射，退出信息使用 `exit_info()`
- 不要为了增加日志破坏关闭文件、唤醒父进程和进入 `ZOMBIE` 的原流程

## 四、wait：先回收，再决定是否睡眠

非阻塞不是完全不检查子进程，而是不在缺少可回收对象时等待。

1. 先扫描全部子进程，找到 `ZOMBIE` 就复制退出状态、回收资源并返回 PID
2. 扫描结束仍无结果时：
   - `flags==1`：释放锁并返回 `-1`
   - `flags==0`：继续调用 `sleep()`，被子进程退出唤醒后再次扫描
3. 所有提前返回都要释放锁，避免死锁或后续进程无法运行

## 五、yield：区分用户现场与内核切换现场

| 结构 | 作用 |
| --- | --- |
| `trapframe` | 保存用户寄存器；用户 PC 从 `epc` 取得 |
| `context` | 保存内核线程切换所需的 `ra`、`sp` 和 `s0`～`s11`，共 112 字节 |

要点：

- <code>&p->context+1</code> 是结构体之后的地址，不能误写成只加一个字节
- 从当前进程之后环形扫描 `proc[]`，逐个持锁检查 `RUNNABLE` 状态，取到候选后释放锁
- 诊断完成后调用原有 `yield()`，让其把当前进程改成 `RUNNABLE`，再经 `sched()` 和 `swtch()` 回到调度器

## 六、为什么输出问题也会影响评分

最初的重复测试出现过 **80 分**：子进程确实运行并退出，但一句 `Child with PID ... begins to run` 被父进程的文字插入，评分器无法匹配连续字符串。

原因：原用户 `printf` 每个字符单独 `write`，单核也能在字符之间被时钟抢占。

最终补充了 **128 字节调用内缓冲**，并把控制台发送改为持锁同步 UART，解决已重现的短行交错。这属于必做实现之外的补充修复，报告中应明确说明。

## 七、同步输出的取舍

- 缓冲提高了短消息连续输出的机会，但不能只合并 `write` 而忽略下层
- 原异步 UART 缓冲满时可能 `sleep`，控制台此时仍持有自旋锁，所以需要配套处理
- 同步发送避免该睡眠路径，代价是忙等待和较长的关中断时间
- 长于 128 字节的消息仍分块；多核内核日志与用户输出也不是统一的全局锁
- **不能**把这次修复描述成所有输出永不交错

## 八、怎样验证最终提交物

验证对象应是 `commit.patch`：

1. 先提交源码
2. 再用 `make diff` 导出相对 `syscall-26-fall-v2` 的差异
3. 在独立干净工作区 `git apply --check` 并实际应用
4. 再重新构建评分

最终同一补丁已通过：

- **5 轮 100/100**
- 额外 **20 轮 yield 测试**
- 格式、无换行、零字节、长字符串及并发短行回归
- 在不含临时程序的默认镜像上通过**三核完整 usertests**

## 九、测试环境问题怎样区分

临时格式测试程序曾挤占 1000 块文件系统的空间：含它的镜像只剩 **242 块**，而 `writebig` 需要 **269 块**，因此出现磁盘耗尽。

移除临时程序、重新生成默认镜像后完整 usertests 通过。这说明：

- 遇到失败要核对代码和测试环境，并保留原始失败日志
- 不能只挑选一次成功结果
- 也不能修改课程评分脚本来消除失败
